# Small project record

Use for multi-session work, not as required paperwork for a simple question.
Keep it with the user's designated private project state, outside the public
skill bundle. With no file access, return the record as text and say it is not saved.

```text
Goal and mode: teach / inspect / make / print preparation / setup
Authorized scope and physical-start status:
Target printer, nozzle, plate, material; slicer if available:
Available capabilities and tests actually passed:
Document identity/destination/revision; units and active component:
Design type, workspace, geometry/history state:
Measurements with source; provisional assumptions:
Parameters and chosen feature route(s):
Accepted interfaces and fit-coupon variant/profile:
Private shared hardware/fit record, if any; tested versus provisional allowances:
Hardware requirements, confirmed dimensions/counts, gaps:
Cloud save: result/version or blocked/unverified:
Local native archive: location, references, restore test or untested:
Exports and slicer projects: exact revision, units, checked/unverified:
Delivered revision folder; native/print files verified there; pending transfers:
Print-pack manifest: part IDs, quantities, plate mapping, reused parts:
Checks: geometry, clearance pairs/phases, slicing, physical feedback:
Unresolved issues and next useful action:
Optional learning: designated source/scope and cycle-record location:
```

Do not store credentials, private chat dumps or unnecessary personal details.
Use actual observed identities and locations; leave unknown fields unknown.
For interrupted operations record the pending action and whether a request may
still be running. A successful transfer, save dialog or API response alone is
not completion. See [checkpoint evidence](data-management.md#save-early-and-say-what-was-saved).
